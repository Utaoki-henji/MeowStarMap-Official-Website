# site/ — 多文件版站点（无视单文件约束的实验分支）

本目录是 `性能/无视约束优化` 分支的产物：把原单文件站点的**数据、图片、字体、图标全部外置**，
落地页只保留 shell。用来回答一个问题——**如果允许打破「单文件自包含」契约，还能快多少**。

> 这不是要替换线上站点，而是一次可行性对照实验。原单文件版本在仓库根目录原样保留，两者可并列比较。

## 结论（实测体积）

| 资产 | 体积 | 何时加载 |
|---|---|---|
| `index.html` | **813,305 B（0.78 MiB）** | 首屏 |
| `assets/fonts/*.woff2` | 485,372 B | 首屏（`font-display:swap`，不阻塞首绘） |
| `data/tutorial.js` | 68,634 B | 首访教程路由 |
| `assets/shots/*.webp` | 4,005,442 B（48 张） | 每页 1–3 张，按需 + 可缓存 |
| `data/dev-docs.js` | 2,088,814 B | 首访 `#/dev` |
| `assets/*.png`、`app-icon.webp` | ~40 KB | 首屏（图标）/ 命中时 |

**落地页首屏 1.24 MiB**（含两张字体），而单文件版是 **8.58 MiB**——相差 **6.6×**；
若只看 HTML 本身是 **0.78 MiB vs 8.58 MiB（11×）**。

## 关键设计

- **数据外置为 classic script**：`data/tutorial.js` 写成 `window.__TUT__={...}`，用
  `document.createElement('script')` 按需注入。没有用 `fetch`/`JSON.parse`，因此
  **不触发 CORS**，`file://` 直开也能加载（这点和 module / fetch 方案不同）。
- **按需加载 + 自动重渲**：`render()` 命中教程/开发者路由时调 `ensureTut()` / `ensureDev()`；
  数据未就绪先渲染占位，加载完成后自动重跑 `render()`。`_tutState` / `_devState` 防重复请求。
- **入口预取**：鼠标移到「进入 / 教程 / 开发者」链接时后台预拉对应数据，切路由近零等待。
- **图片改普通 `<img src>`**：浏览器可单独缓存、`loading="lazy"` 生效、不再有 base64 的 33% 膨胀；
  支持将来加 `srcset` 做响应式。
- **字体外置**：woff2 单独文件、可缓存，`@font-face` 仍是 2 条（内容不变，仅换源）。
- **图标外置**：favicon / apple-touch-icon / 应用图标改为文件，顺带修掉「iOS 读不了 data: 图标」。

## 本地预览

必须用 HTTP（字体走 `url()`，`file://` 下部分浏览器会因 CORS 拒绝加载字体，虽然会回退系统字体）：

```bash
cd site
python -m http.server 8080
# 打开 http://localhost:8080/
```

## 重新生成

`site/` 全部是生成物（除 README），由工具链从仓库根目录的单文件 HTML 重建：

```bash
python perf/tools/split_site.py
```

## 与单文件契约的差异（本分支有意为之）

| 项 | 单文件版 | 本目录 |
|---|---|---|
| 外部资源 | 恒为 0 | 53 个（HTML/CSS/JS/字体/截图） |
| `file://` 双击 | 完整可用 | 可用但字体可能不加载（CORS），回退系统字体 |
| `#tut-data` / `#dev-data` 内联块 | 保留 | 已移除，改为外部脚本 |
| 零外链不变量（探针口径） | 守护 | **不再成立**（r37/r38/r42/r45 的零外链断言会红） |
| 缓存粒度 | 整站一个文件，改一处全失效 | 按资产缓存，改数据不影响图片 |
